# 화면 흐름

## 공통 원칙

- 모든 UI 문구는 한국어로 작성한다.
- 한 화면에서 하나의 주요 행동만 제공한다.
- 화면 하단 또는 우측에는 다음 행동 버튼을 명확히 배치한다.
- 생성 이미지가 존재하는 화면에서는 이미지 미리보기가 가장 큰 영역을 차지한다.
- 전문 디자인 편집기처럼 도구막대, 레이어 패널, 속성 패널을 만들지 않는다.

## 라우트

| 경로 | 화면 | 주요 목적 |
| --- | --- | --- |
| `/` | 작업 시작 | 새 홍보물 만들기, 최근 작업 보기 |
| `/projects/new/purpose` | 용도 선택 | 홍보물 용도와 크기 선택 |
| `/projects/new/copy` | 문구 입력 | 홍보 문구 입력 |
| `/projects/new/assets` | 사진/매장 선택 | 메뉴 사진, 매장 정보 입력 |
| `/projects/new/style` | 분위기 선택 | 분위기, 참고 이미지 입력 |
| `/projects/:id/generate` | 생성 진행 | 최초 이미지 생성 상태 표시 |
| `/projects/:id/result/:versionId` | 결과 확인 | 생성 결과 확인, 수정/재구성/다운로드 |
| `/projects/:id/annotate/:versionId` | 메모 수정 | 포스트잇 메모 추가 |
| `/projects/:id/compare/:beforeId/:afterId` | 전후 비교 | 수정 전후 비교 후 적용 |
| `/projects/:id/reframe/:versionId` | 비율 재구성 | 다른 비율 선택 후 재생성 |
| `/projects/:id/history` | 히스토리 | 이전 버전 확인 및 복원 |

## 1. 작업 시작

### 화면 요소

- 서비스명 `만드롱`
- 주요 버튼 `새 홍보물 만들기`
- 최근 작업 목록
- 빈 상태 문구 `아직 만든 홍보물이 없어요`

### 상태

- 최근 작업 로딩
- 최근 작업 없음
- 최근 작업 조회 실패

### 예외 처리

- 조회 실패 시 `최근 작업을 불러오지 못했어요`와 `다시 시도` 버튼을 표시한다.

## 2. 용도 선택

### 입력

- 홍보물 유형: 포스터, 배너, 메뉴판, SNS 정사각형, SNS 스토리
- 홍보물 유형 추가: X배너. 사용자는 600x1800 기준으로 이해하되, 이미지 생성 모델 제약 때문에 실제 생성 요청은 608x1808로 보낸다.
- 크기 프리셋
- 직접 크기 입력: 가로/세로 px 단위

### 다음 조건

- 유형과 크기를 선택해야 `다음` 버튼이 활성화된다.
- 직접 크기는 가로/세로 각각 256px 이상 4096px 이하일 때만 유효하다.
- 이미지 생성 모델 제약에 맞춰 직접 크기는 16px 단위로 자동 조정한다. 예: 600x1800 입력 시 608x1808로 생성한다.

### 저장

- 선택 즉시 Pinia 임시 작성 상태에 저장한다.
- `다음` 클릭 시 서버에 `Project`와 `CreativeBrief` 초안을 생성한다.

## 3. 문구 입력

### 입력

- 홍보물에 넣고 싶은 전체 문구를 하나의 입력란에 자유롭게 입력한다.
- 가격, 혜택, 기간, 안내 문구도 같은 입력란에 함께 적는다.

### 검증

- 전체 문구는 1자 이상 1,000자 이하
- 줄바꿈 허용

### 예외 처리

- 너무 긴 문구는 입력란 하단에 `문구가 너무 길어요. 핵심 내용만 남겨주세요`를 표시한다.

## 4. 사진/매장 선택

### 입력

- 메뉴 사진 업로드: JPG, PNG, WEBP
- 최대 파일 수: 8개
- 파일당 최대 크기: 20MB
- 매장명
- 메뉴명
- 가격
- 주소 또는 지역
- 전화번호 또는 주문 방법

### 상태

- 업로드 대기
- 업로드 중
- 업로드 완료
- 업로드 실패

### 예외 처리

- 음식 사진이 없으면 진행 가능하되 생성 프롬프트에 `제공된 메뉴 사진 없음`을 명시한다.
- 업로드 실패 파일은 개별 재시도 버튼을 제공한다.

## 5. 분위기 선택

### 입력

- 분위기 칩: 깔끔한, 따뜻한, 고급스러운, 활기찬, 전통적인, 귀여운, 프리미엄, 가성비 좋은
- 자유 분위기 설명
- 참고 디자인 이미지 업로드: 최대 3개

### 검증

- 분위기 칩 또는 자유 설명 중 하나 이상 필요
- 참고 이미지는 선택 사항

## 6. 생성 진행

### 동작

- `POST /api/v1/projects/{project_id}/generations` 호출
- 응답의 `generation_id`를 기준으로 상태 폴링 또는 서버 이벤트 구독

### 화면

- 큰 미리보기 영역의 스켈레톤
- 문구 `홍보물을 만들고 있어요`
- 보조 문구 `음식, 가격, 배경, 구도를 함께 구성하고 있어요`

### 완료

- 성공 시 `/projects/:id/result/:versionId`로 이동한다.
- 실패 시 같은 화면에서 오류와 재시도 버튼을 표시한다.

## 7. 결과 확인

### 화면 요소

- 생성 이미지
- 버튼: `메모로 수정`, `다른 비율로 만들기`, `다운로드`, `히스토리`
- 버전 정보: 생성 시각, 상태

### 애니메이션

- 이미지 로드 완료 시 `opacity: 0 -> 1`, `scale: 0.985 -> 1`
- 지속 시간 280ms
- easing `ease-out`

### 예외 처리

- 이미지 파일이 없으면 `이미지 파일을 찾지 못했어요`와 `다시 생성` 버튼을 표시한다.

## 8. 메모 수정

### 화면 요소

- 이미지 캔버스
- 포스트잇 메모
- 선택 영역 박스
- 메모 목록
- 버튼: `수정본 만들기`

### 상호작용

- 사용자가 이미지 위를 클릭하면 메모가 추가된다.
- 드래그하면 선택 영역이 지정된다.
- 메모에는 자연어 수정 요청을 입력한다.
- 메모는 생성 이미지 위 좌표를 기준으로 저장하되 원본 이미지 크기 대비 정규화 좌표로 저장한다.

### 검증

- 최소 1개 메모 필요
- 각 메모는 1자 이상 300자 이하
- 선택 영역 없이 전체 이미지 메모로 저장 가능

## 9. 전후 비교

### 화면 요소

- 좌측: 수정 전
- 우측: 수정 후
- 버튼: `수정본 적용`, `다시 수정`, `이전으로`

### 동작

- `수정본 적용` 클릭 시 해당 버전을 프로젝트의 `current_version_id`로 지정한다.
- 적용하지 않은 수정본도 히스토리에 보관한다.

## 10. 비율 재구성

### 입력

- 대상 비율 선택
- 유지할 내용 선택: 문구, 메뉴 사진, 가격, 분위기

### 동작

- 현재 버전을 기준으로 새 비율의 이미지를 생성한다.
- 기존 이미지를 단순 크롭하지 않고 `gpt-image-2`에 재구성 요청을 보낸다.

## 11. 다운로드

### 입력

- 형식: PNG, JPEG, PDF
- JPEG 품질: 기본 90

### 동작

- `POST /api/v1/versions/{version_id}/exports`
- 완료 후 파일 다운로드 URL 제공

### 예외 처리

- PDF 변환 실패 시 PNG/JPEG 다운로드는 계속 가능하게 유지한다.

## Pinia 상태

| 스토어 | 책임 |
| --- | --- |
| `useDraftStore` | 새 작업 입력값 임시 저장 |
| `useProjectStore` | 현재 프로젝트와 버전 상태 |
| `useUploadStore` | 업로드 진행률과 실패 상태 |
| `useGenerationStore` | 생성/수정/재구성 작업 상태 |
| `useToastStore` | 짧은 오류/완료 메시지 |
