# 포스트잇 메모 수정 흐름

## 목표

사용자는 완성 이미지에서 잘못된 부분에 포스트잇 메모를 붙인다. 서버는 원본 이미지, 선택 영역, 수정 메모를 함께 `gpt-image-2`에 전달해 새 수정 버전을 만든다.

사용자는 이미지의 구성 요소를 직접 편집하지 않고 자연어로만 수정 의도를 전달한다.

## 주석 데이터

좌표는 화면 픽셀이 아니라 원본 이미지 크기 대비 정규화 좌표로 저장한다.

```json
{
  "note": "메뉴 이름을 갈비탕으로 정확히 바꿔주세요",
  "x": 0.42,
  "y": 0.18,
  "width": 0.28,
  "height": 0.1,
  "color": "yellow"
}
```

- `x`, `y`: 좌상단 기준 0~1
- `width`, `height`: 선택 영역이 있을 때만 사용
- 영역 없이 클릭 메모만 있으면 전체 이미지 맥락 수정으로 처리한다.

## 화면 상호작용

1. 결과 화면에서 `메모로 수정`을 클릭한다.
2. 이미지가 큰 작업 영역으로 표시된다.
3. 사용자가 이미지 위를 클릭하면 포스트잇 메모가 생긴다.
4. 사용자가 드래그하면 선택 영역이 생기고 메모 입력창이 열린다.
5. 사용자는 수정 요청을 한국어로 입력한다.
6. 메모는 우측 또는 하단 목록에도 표시된다.
7. `수정본 만들기`를 클릭하면 메모를 저장하고 수정 생성 요청을 보낸다.

## 클라이언트 상태

| 상태 | 의미 |
| --- | --- |
| `idle` | 메모 작성 전 |
| `placing` | 클릭 또는 드래그 중 |
| `editing_note` | 메모 입력 중 |
| `saving` | 주석 저장 중 |
| `submitting` | 수정 생성 요청 중 |
| `failed` | 저장 또는 요청 실패 |

## 검증

- 메모는 최소 1개 필요하다.
- 메모 내용은 1자 이상 300자 이하이다.
- 좌표는 0~1 범위를 벗어나면 클라이언트에서 보정하고 서버에서 다시 검증한다.
- 대상 버전이 프로젝트에 속하지 않으면 서버가 404로 응답한다.
- 이미 처리 중인 수정 작업이 있으면 새 수정 요청은 409로 거절한다.

## 서버 처리

1. `POST /versions/{version_id}/annotations`로 주석을 저장한다.
2. 서버는 대상 버전과 프로젝트를 검증한다.
3. 서버는 좌표 범위와 메모 길이를 검증한다.
4. 서버는 `annotations` 테이블에 메모를 저장한다.
5. `POST /versions/{version_id}/edits`로 수정 생성을 요청한다.
6. 서버는 주석 ID 목록이 같은 버전에 속하는지 확인한다.
7. `generation_jobs`에 `edit` 작업을 생성한다.
8. 프로젝트 상태를 `editing`으로 변경한다.
9. 백그라운드 작업이 원본 이미지와 주석 정보를 사용해 수정 프롬프트를 조립한다.
10. `gpt-image-2`에 이미지 수정 요청을 보낸다.
11. 결과를 새 이미지 자산과 새 버전으로 저장한다.
12. 전후 비교 화면에서 사용할 `before_version_id`, `after_version_id`를 응답 상태 조회에서 제공한다.

## 수정 프롬프트 구성

서버는 다음 정보를 포함한다.

- 기준 이미지
- 수정하지 말아야 할 내용: 전체 분위기, 메뉴 사진의 정체성, 정확한 가격과 매장 정보
- 각 메모의 위치와 선택 영역
- 각 메모의 수정 요청
- 포스트잇 자체는 최종 이미지에 보이지 않게 하라는 지시

예시 구조:

```text
기준 이미지를 유지하되 아래 메모만 반영해 수정한 완성 홍보 이미지를 만들어라.
포스트잇이나 선택 박스는 최종 이미지에 포함하지 않는다.

메모 1:
- 위치: 이미지 가로 42%, 세로 18%, 너비 28%, 높이 10%
- 요청: 메뉴 이름을 갈비탕으로 정확히 바꿔주세요.

유지:
- 따뜻하고 깔끔한 식당 포스터 분위기
- 음식 사진의 종류와 구도
- 가격 9,900원
```

## 전후 비교

수정 작업 성공 후 사용자는 비교 화면으로 이동한다.

- 왼쪽: 수정 전 버전
- 오른쪽: 수정 후 버전
- 기본 확대 비율은 동일하게 유지한다.
- `수정본 적용` 클릭 시 `POST /versions/{after_version_id}/apply`를 호출한다.
- 적용하면 프로젝트의 현재 버전이 수정본으로 바뀐다.
- 적용하지 않아도 수정본은 히스토리에 남는다.

## 예외 처리

| 상황 | API 코드 | 사용자 메시지 |
| --- | --- | --- |
| 메모 없음 | `VALIDATION_ERROR` | 수정할 내용을 메모로 남겨주세요 |
| 대상 버전 없음 | `VERSION_NOT_FOUND` | 수정할 이미지를 찾지 못했어요 |
| 처리 중 작업 있음 | `GENERATION_IN_PROGRESS` | 지금 만드는 수정본이 끝난 뒤 다시 시도해주세요 |
| 이미지 파일 누락 | `ASSET_NOT_FOUND` | 원본 이미지 파일을 찾지 못했어요 |
| 수정 실패 | `GENERATION_FAILED` | 수정본을 만들지 못했어요 |

## 주석 스냅샷

수정 요청이 들어가면 서버는 사용한 주석 목록을 JSON으로 `storage/annotations`에도 저장한다. DB가 원본 데이터이고 JSON은 재현과 디버깅을 위한 스냅샷이다.
